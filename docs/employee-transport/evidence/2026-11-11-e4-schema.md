## 3. R2 decisions adopted (doc 17 §2.6 recommended defaults; recorded in the migration headers; owner review at the P6 gate)

- **Q-a** passenger data on plan stops: plan operator-owned (`companyId` = operator); passenger stops carry
  `customerCompanyId` (FK Company Cascade) and `bookingId?` (FK TransportBooking SetNull).
- **Q-b** driver identity: `RouteAssignment.driverId` FK Driver; `assigneeUserId` dropped (D5).
- **Q-c** vehicle purge vs plan history: FK SetNull on `objectId` / `driverId`, history kept.
- **Q-d** menu key: ETMS key `etms_planning` (`ETMS_PLANNING_MENU`) under company feature `etms`; no `route_plans` key,
  no Manager preset in `SYSTEM_ROLES`. Not added to `MENUS` here (the web planner adds it with its page, WP 4.5).

## 4. Personal points (snapshot policy)

- A plan stop is personal iff `profileId` is set (then `poiId` is NULL, CHECK `RoutePlanStop_personal_check`). Its
  `lat` / `lng` are a snapshot copied at plan build from the **booking's** pickup / drop point (consent-gated at the source:
  the generator creates no personal point without routing consent); never copied from `EmployeeTransportProfile.homeLat /
  homeLng`. `RoutingJob.input` and `RoutePlanVersion.snapshot` never carry coordinates or names (contract).
- Erasure (`eraseTransportData` → `eraseRoutingPlanPoints`): personal plan stops coarsened to 2 decimals, name and snapped
  point removed, assignment geometry cleared (`TransportErasure.planStops`).
- Routing-consent withdrawal (`applyRoutingConsentWithdrawal` → `withdrawRoutingPlanPoints`): personal stops deleted from
  DRAFT / OPTIMIZING / PLANNED plans (plan `version + 1`, so a running optimise job is stale) and coarsened in PUBLISHED /
  CANCELLED plans; geometry cleared (`planStopsRemoved`, `planStopsAnonymised`).
- Not done (left for the Lead): snapped columns on `EmployeeTransportProfile` / `TransportBooking` (doc 15 §10 E4 line).
  They are non-FK columns on existing tables, outside this brief; plan stops carry the snapped point instead.
