| **L6** stuck OPTIMIZING plans outlive retention | **Fixed** | `retention/stuck-route-plans.ts`, step `routePlansStuck`: OPTIMIZING plans past the cutoff whose jobs are all terminal / missing, or every such plan when `ETMS_ROUTING` is off; their still-active jobs become CANCELLED (error code CANCELLED, ids only), then the plan is deleted (stops cascade). | **L7** lease owner per process | **Fixed** | `job-worker.ts`: `lockedBy = <host>-<pid>-<rand>:<claim UUID>` per claim; heartbeat, progress, succeed and settle use it. | `worker-lifecycle.spec.ts`: same worker, lease expires, another slot re-claims; the stale run cannot renew and its late result is refused while the second claim owns the job. `routing-jobs.db-test.ts` expects the token form. |
| **L8** non-composite plan FKs | **Fixed (triggers, documented)** | Composite FKs are not usable: every link is `ON DELETE SET NULL` on a nullable column whose partner (`planId`, `companyId`, `providerCompanyId`) is NOT NULL, and a composite FK's SET NULL nulls the partner too (PostgreSQL's column-list SET NULL cannot be modelled in the Prisma schema, so `migrate diff` would no longer be empty). The migration adds BEFORE INSERT / UPDATE triggers instead: `RoutePlanStop.assignmentId` → assignment of the same plan; `RoutingJob.planId` → plan of the same company; `TransportTrip.routePlanId` → plan of the trip's operator, `routeAssignmentId` → assignment of that operator (and of `routePlanId` when set). Clearing a link (FK SET NULL during a purge) is never checked. `TransportTrip` gets a trigger only (brief SHARE ROW EXCLUSIVE lock, no scan or rewrite, `lock_timeout 5s`). | `e4-secfix.db-test.ts` (cross-plan stop, cross-company job, cross-operator trip links refused; plan purge still nulls both trip links and the job link); psql check on the upgraded database (below). |
| **L9** service hardening / token separation | **Fixed** | Worker unit: `ProtectSystem=strict` (writes nothing, so no `ReadWritePaths`), `ProtectHome`, `PrivateDevices`, `IPAddressDeny=any` + `IPAddressAllow=localhost`, `RestrictAddressFamilies`, `MemorySwapMax=0`, empty `CapabilityBoundingSet`, `RestrictNamespaces`, `LockPersonality`, `SystemCallArchitectures=native`, kernel / clock / hostname protections. Optimiser unit: the same additions. Token: `veetrax-api` and `veetrax-routing-worker` set `OPTIMIZER_TOKEN_FILE=/etc/veetrax/optimizer.env` (the API reads the env-file format or a bare token; the file wins over `OPTIMIZER_TOKEN`); gateway, processor, notifier and summarizer get `InaccessiblePaths=-/etc/veetrax/optimizer.env`. Units all run as `veetrax`, so separation is by systemd namespace, not file mode. Installer: no longer asks to copy the token into `.env`; an existing `/etc/veetrax` keeps its owner and mode. `health-gate.sh`: the header file is a global removed by the EXIT trap, with INT / TERM / HUP traps so an interrupted gate also cleans up. | `optimizer.client.spec.ts` (file wins, env-file format, unreadable / empty file → off); `health-gate-test.sh` new case (FAIL run and SIGTERM mid-poll leave no temp file); `systemd-analyze verify` on the units (no unknown directive); optimiser `test_server.py` + `test_solver.py` run under `systemd-run` with the optimiser unit's sandbox properties: 22 passed. |
