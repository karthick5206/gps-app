Fixes for the independent E2 security review (M1–M5, Low findings) and the E2 QA report (B1–B10, WP 2.4–2.6), on

## Migration `20261115090000_etms_people` amended (not shipped yet)

- Consent: columns `evidenceRef`, `note`; CHECKs `EmployeeTransportConsent_on_behalf_check` and
  `EmployeeTransportConsent_offline_evidence_check`.
- New table `TransportPassengerNotice` (in-app notification intent; composite FK to the profile, Cascade).
- Trigger `etms_evidence_guard` on `EmployeeTransportConsent` and `TransportConsentNotice`: UPDATE / DELETE refused
  unless the transaction ran `SET LOCAL veetrax.evidence_write = 'erasure'` (UPDATE) or `'purge'` (DELETE).
  `PurgeService` sets `'purge'` in every purge transaction.
- Idempotent data backfill (QA B3): `etms_passengers` on unchanged E1a "Transport admin" / "Transport dispatcher"
  templates (same name, seeded description and scope, not system). Production had 0 such companies.
- **Any database that already applied the earlier version (e.g. `veetrax_assess`) must be re-created / re-migrated:**
  the migration checksum changed.

### Release note (deploy)

1. `prisma migrate deploy` applies `etms_people` including the role backfill: companies that switched employee
   transport on before this release get the Passengers menu in their unchanged "Transport admin" (view / create /
   edit / delete / export) and "Transport dispatcher" (view / edit) roles. Roles a company renamed or changed are not
   touched; their admin grants Passengers in Roles by hand. Users see the menu after their next sign-in / cache refresh.
2. `GEOCODER_URL` must be a loopback / private / internal host (for example `http://127.0.0.1:2322`). A public host
   makes ETMS address search and import geocoding refuse with 503 `GEOCODER_NOT_PRIVATE` (warned at start-up).
3. Repo: `.gitattributes` keeps `apps/api/prisma/migrations/**/migration.sql` LF on every platform (QA B8). Verified:
   all 62 tracked migration files in the working tree are byte-identical to the committed (LF) blobs after the rule
   (`sha256(git show HEAD:<file>) == sha256(<file>)`, 62 / 62), so already-applied production checksums (Linux LF
   checkout) are unchanged; the index already held LF (`git ls-files --eol`: `i/lf` for all).

## What changed (API)

| Item | Change |
|---|---|
| M1 | An admin / dispatcher chooses only the initial password of a login that never signed in and has no password; otherwise 409 `PASSWORD_RESET_REQUIRED`. New `POST /transport/passengers/:id/app-access/reset` and `POST /drivers/:id/login/reset`: one-time token (72 h, earlier tokens cancelled, hash stored), redeemed at `/reset-password` (sets own password, revokes all sessions). Every credential change, disable, unlink, archive, import archive, driver deactivate / delete revokes all sessions and publishes G5. Audited on `User`; passenger notified in-app. |
| M2 | On-behalf grants only as a recorded offline consent (`evidenceRef` + `note`, channel `ADMIN_RECORDED_OFFLINE`); otherwise 403 `CONSENT_SELF_ONLY`. Withdrawals channel `ADMIN_ON_BEHALF`. In-app notice record per action (`GET /me/transport/notices`); evidence shown in consent history. |
| M3 | No coordinates in list rows (every role); dispatchers get no home point at all, only `pickup` on the detail view with routing consent; admin detail reads ACCESS-audited with `homeLocation: true`. |
| M4 | CSV export only ever contains the caller's own company's passengers; provider list reads ACCESS-audited in the customer's log. |
| M5 | `POST /transport/passengers/:id/erase` (archived, FULL, `etms_passengers:delete`, confirm = employee code): **L5 default, pending owner confirmation of L5** — anonymise in place, keep statistics and consent history without identity, scrub the passenger's audit values, delete in-app notices, disable + unlink the login (transport-only User anonymised). |
| L1 | One generic `IDENTITY_IN_USE` message; refusals audited with masked contacts; 10 refusals / hour / caller → 429 `IDENTITY_RATE_LIMITED`. |
| L2 / B1 / B2 | Re-linking re-enables only logins ETMS itself disabled (holding only the template role); another contact on a linked login → 409 `LOGIN_ALREADY_LINKED`; a password is never overwritten or silently ignored; `invite.passwordSet` / audit `passwordChanged` only when a password was set. |
| L3 | Import archive and driver deactivate / delete disable the login and revoke sessions. |
| L4 / L5 / B5 | Dispatchers: no consent records, history only profile entries; login identifiers masked in list rows and for STANDARD. |
| L9 / L10 | Evidence trigger (above); composite tenant FKs where doc 15 §1.4 asks (consent, passenger notice). |
| L11 | `GEOCODER_URL` must pass the G6 probe host policy (`isLocalHost`). |
| L12 | Isolation-matrix regex fixed (`/:\w+/`); verify for history, consents, geocode, import report; extra checks for CSV export, provider read audit, pickup gating, M2. |
| L13 | Seats / driver logins stay on fleet grants (documented, owner decision pending). |
| B4 | `currentVersion` (string) forwarded on `CONSENT_NOTICE_OUTDATED`, also on `/api/me/transport`. |
| B6 | People DB test uses the shared `dbDescribe` guard (`veetrax_assess` refused under `CI=true`). |
