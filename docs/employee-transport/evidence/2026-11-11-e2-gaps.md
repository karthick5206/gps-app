## 1. What changed

| Gap | API | Web |
|---|---|---|
| 1 Vehicles list | `GET /api/transport/vehicles` now lists every own vehicle (type VEHICLE) in the caller's branch scope (`objectScopeWhere`: whole company, or own branches + assigned objects; shares never), paged / searched (`q`, `page`, `pageSize`, `sort` name / plateNumber, `status`, `seats=set|unset`), `profile: null` while seats were never set. | Vehicle seats page reads only this endpoint; the merge with `/objects` is gone. New "Seats not set / set" filter. |
| 2 Consent notice | New table `TransportConsentNotice` (doc 15 §4.3a): company-level, per purpose, immutable versions `v1, v2…`, `effectiveFrom`. `GET/POST /api/transport/consent-notices` (read: Transport settings or passengers view; publish: Transport settings edit + whole-company role). `GET /api/me/transport/consent/notices` (passenger). A grant records the current version server-side; no notice → 409 `CONSENT_NOTICE_MISSING`; a shown version that is no longer current → 409 `CONSENT_NOTICE_OUTDATED`; a withdrawal records the version it withdraws. | Transport settings: "Consent notices" panel (write / edit text, optional effective date, version list). Consent panel shows the notice text and version before "Employee agreed: record consent"; the version is no longer typed. |
| 3 Passenger history | `GET /api/transport/passengers/:id/history` from the audit log (profile, consent rows, User login changes; ACCESS reads for the admin). Redaction in `passenger-history.ts`: home / health / emergency values only "changed"; dispatcher: no home-location or emergency-contact fields, no reads, no IP; provider (VIEW_PASSENGER_MINIMAL): MINIMAL fields only (short name, office, status, default stop with routing consent), contacts per agreement, no actor / IP, no consent or login entries; no grant → 404. The read is audited (`what: history`, under the customer company for providers). | History action in the passenger list (every row) and in the editor header; sheet with readable titles and a field table. |
| 4 Geocode confidence | `photonConfidence()` maps Photon's `type` (house + number 0.9, house 0.8, street 0.6, other 0.5, locality 0.4, district 0.35, city 0.25, county 0.15, state 0.1, country 0.05); null without a type. Photon's HTTP API does not return its `importance` score (ranking only), so match type is the only usable signal. Stored as `homeGeocodeConfidence` for server geocoding and import; the import warns `GEOCODE_LOW_CONFIDENCE` below 0.6 (locality or coarser). Self-hosted Photon only (unchanged `GeocodingService`). | Address matches show "Exact address / Street / Area only: check the pin"; a picked candidate keeps its confidence. |
| 5 Login removal | `DELETE …/app-access?mode=` and `DELETE /api/drivers/:id/login?mode=`: `disable` (default, unchanged behaviour: transport role removed or User deactivated, link kept) or `unlink` (same, then `userId` cleared). The User is never deleted. Re-linking a disabled transport-only login by its contact now re-enables it (`REACTIVATED`); a disabled fleet login stays the Users admin's decision (409 `INVALID_STATE`). | App login panel: "Disable login" and "Unlink login", each with its own confirmation text. |
